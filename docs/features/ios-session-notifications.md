# Expo iOS 会话状态与任务提醒

适用于 `packages/happy-app` 的 Expo iOS 客户端。独立 Swift 客户端和 Live Activities 不在本次范围。

## 展示与操作

- 会话列表用蓝色“运行中”、绿色“已完成”、橙色权限/回答提示、红色“执行失败”配合图标展示状态。失败来自明确的 `turn-end: failed`，不把断线当作失败。
- 全局顶部保留“已完成 N · 待处理 N”入口，展开后显示提醒列表，点击进入对应会话。正在查看的会话、运行中的会话、归档及隐藏子会话不重复提示。
- 新提醒显示约 3.5 秒的短横幅；关闭横幅或列表不会标记已读。App 前台时可产生一次触感，实时状态和后到达的持久化事件不会重复触发同一次状态的触感。
- Codex 失败只发送失败提醒，并在系统通知和 App 横幅中保留错误类型（如 `serverOverloaded` 表示模型容量不足）；手动取消不发送完成通知。App 等待明确的结束事件，不把“停止思考”直接当作成功。后续重试成功按新一轮完成展示，旧失败及延迟事件不会覆盖新结果。
- 账号设置增加“始终提醒手机”和“App 内触感提醒”。前台系统横幅与声音沿用静默策略，由 App 内提醒承接。
- App 图标角标展示需要关注的会话数量；系统通知按会话分组。声音、锁屏展示仍受 iOS 通知权限和系统设置控制。

## 人工介入提醒已移除

已移除“等待人工处理”全局弹窗、持续入口、会话输入框上方的专用回复提示，
以及 CLI 的 `request_human_intervention` MCP 工具、专用推送和对应提示词。
已有会话中的人工介入状态不再阻塞会话展示、遮盖真实权限请求或抑制后续完成通知；
旧版 App 发送的关联回复按普通聊天消息投递，不再等待专用状态确认。

现有权限审批、agent 提问和普通会话通知继续使用原有链路。
协议字段和 Relay 对旧事件的支持保留，用于兼容旧客户端与历史数据；
新版 App 不把历史 `intervention` 通知显示为人工介入或完成提醒。
这套移除不补充 Git 审批或本机凭据提示的捕获能力；相关漏报需要针对实际请求单独排查。
CLI 源码和 App 需更新后分别生效，源码修改不包含 CLI 安装、Relay 部署或 OTA。

## 数据与同步

复用已有 MMKV、账户 KV、Socket.IO 和版本校验，无新增依赖或数据库迁移。

1. CLI 调用现有 `/v1/sessions/:id/push-event` 时，服务端先将最新提醒保存到账户 KV 命名空间 `session-attention-v1:<sessionId>`，再广播和发送推送。重复事件保留已读状态，已经投递的通知不重复发送，失败投递允许重试。
2. 此命名空间保存非正文的投递元数据：`kind`、`eventId`、`seq`、`at`、`read` 和可选 `pushDelivered`、`errorCode`。`errorCode` 仅保存错误类型，不保存原始错误消息。这是服务端可读的通知元数据，不包含会话标题、消息正文、密钥或凭证；普通用户内容的加密方式不变。
3. 客户端按账户和服务地址缓存记录、未读集合及离线待发送回执。在启动、恢复前台、重连及会话列表更新时批量获取相应 KV；在线更新复用 `kv-batch-update`。
4. 查看会话后只确认对应事件，使用 KV 版本完成已读写入。离线时先保留本地回执，恢复后重试；旧事件的回执不能覆盖新一轮提醒。明确失败事件同样先保存在本地待发送队列，再同步到账户 KV。
5. 只根据在线运行状态推断的完成标记可在本机恢复。跨设备补录和用户离线期间的提醒依赖生产端发出相应会话事件；历史上没有发出的事件不会被凭空补造。每个会话保留最新提醒，不提供逐轮通知历史。

## 推送焦点策略

客户端在 Socket.IO 握手及 `app-state` 中携带 `viewingSessionId` 和 `alwaysPushToPhone`，焦点或设置变化时更新。

仅当活跃 UI 客户端明确正在查看通知对应的会话时，服务端才抑制手机推送。查看其他会话、普通首页、旧客户端未提供会话焦点或焦点查询失败时均发送。开启“始终提醒手机”后不按该焦点抑制。编码会话及机器连接始终不算用户正在阅读。

## 验证

移除回归覆盖真实 HTTP/STDIO MCP 工具列表、历史状态兼容、真实权限请求优先级、
旧版关联回复的消息投递，以及历史状态不抑制后续完成通知。旧人工介入专用 E2E 脚本已删除。

运行 `pnpm exec node packages/happy-app/scripts/ios-session-notifications.e2e.mjs`，需要本地 Expo Web（默认 `http://127.0.0.1:8989`）及已有 CLI 构建。脚本使用临时本地服务和测试账户，验证真实 Socket.IO、重启恢复、两个独立客户端的已读同步，并通过仅开发环境开放的 `/dev/session-notifications` 检查移动端组件布局、提醒列表、明确失败和点击跳转。

Codex 完成与失败回归使用 `pnpm exec node packages/happy-app/scripts/codex-session-notifications.e2e.mjs`，环境要求相同。脚本通过真实 Relay、Socket.IO 和 KV 检查：停止思考不能提前报成功、失败错误类型、成功重试、延迟失败不能覆盖新结果、刷新恢复、手动取消、异常中断及提醒跳转，并收集页面、Console 和网络错误。截图与报告保存在 `.e2e-artifacts/codex-session-notifications-<run-id>/`。

浏览器移动尺寸预览不等于 iOS 真机验收。APNs/Expo 到锁屏的实际投递、系统权限、触感及原生安全区仍需在 iPhone 上验证。本次不执行构建分发或部署。
