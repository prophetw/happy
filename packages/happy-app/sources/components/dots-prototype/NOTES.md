# Dots 独立页面交互原型（已选定 B，非正式功能）

设计问题：在 Happy 内，怎样让用户找到长期助理、了解工作进展，并返回同一个 Dot 的对话？

2026-11-05 用户明确选择方案 B：紧凑助理目录与旁侧待处理区。宽屏左右排列，窄屏上下排列。
已删除 A/C 比较布局、底部方案切换器和键盘切换逻辑；所有原型入口统一显示 B。
Dot 详情继续采用对话为主、工作栏为辅的结构，原型仍只使用内存示例数据。

## 启动

在 Happy 仓库根目录运行（已有依赖，无需安装）：

```sh
BROWSER=none EXPO_OFFLINE=1 pnpm --filter happy-app web --host localhost --port 8097
```

手动打开 `http://localhost:8097/dots?prototype=1`，默认显示已选定的 B 布局。
旧链接中的 `variant=A/B/C` 参数不再切换布局，统一显示 B。底部保留示例状态、断线和重置入口。
使用原有 Happy 布局；已登录的宽屏环境显示原侧栏。原型内容不依赖登录或真实 Dot 数据。
开发模式可直接预览；生产 Web 预览需要构建时显式设置 `HAPPY_DOTS_PROTOTYPE=1`
（Docker build arg，映射到 `EXPO_PUBLIC_DOTS_PROTOTYPE=1`），并通过 `prototype=1` 进入。
该构建开关默认关闭，普通 `/dots` 继续使用既有入口；原生 App 的生产模式不开放原型。
公网构建沿用 `/happy` 基址，预览地址为 `/happy/dots?prototype=1`。

## 可体验的流程

- 首页 → 进入 Dot → 对话；桌面宽内容区显示可收起的工作栏，窄屏以对话/工作/记忆切换。
- 新建 Dot → 填写名称、职责 → 创建并进入临时专属对话。
- 发送交办 → 脚本生成待确认示例 → 模拟确认 → 模拟执行结束 → 待验收。
- 核对全部示例验收条件 → 模拟通过，或返工；首页、工作项和对话共同更新。
- 工作项 → 示例执行会话 → 返回原工作项或 Dot 对话。
- 当前 Dot 记忆 → 添加/编辑 → 确认保存；删除需再次确认，其他 Dot 的记忆不受影响。
- 底部调节按钮展开完整状态，支持模拟断线和重置；刷新也恢复种子数据。

## 实现范围

复用已有 React、React Native、Expo Router、Unistyles、StyledText 和 Ionicons，不增加依赖。
原型不读取业务状态、不发送 Happy 消息、不调用模型、不运行执行 Agent、不写持久数据。
外围 Happy 壳仍沿用原有登录/同步；已有登录时可能正常读取账号数据。
状态与回复均为示例，验收勾选只演示交互，不能证明真实产物或测试结果。
断线开关模拟状态，阻止示例派发与工作项状态提交；不是网络故障诊断工具。

## 评审与清理

首页方案已选定 B；A/C 比较代码和方案切换工具已移除。
